你按下回车的瞬间

一条消息从你的指尖出发，穿越前端、IPC 桥、Rust 后端、模型 API，再回到屏幕上的完整旅程。

你在 Hebbian 的输入框里打好字，按下 Enter。不到一秒，助手就开始回复了。但在这「不到一秒」里，发生了很多事情——整个过程像一场精心编排的接力赛。

这个课程会追踪每一条消息的完整旅程：从你按下回车的瞬间，到助手的文字逐字出现在屏幕上。你会理解每个环节在做什么、为什么这么设计，以及——当事情出了岔子——该从哪里下手排查。

sendMessage 是 Tauri 的 invoke 调用，底层通过 Channel 对象传递事件流。这个 Channel 很有意思——在 Tauri 桌面端，它是真正的 IPC channel；在 Web 端（hebweb），它退化为一个 WebSocket 监听器。

💡
为什么用 Channel 而不是轮询？

如果前端每秒问一次「有新消息吗」，响应会延迟最多 1 秒，而且浪费 CPU。Channel 是「推送」模式——后端有事件就立刻推给前端，延迟是亚毫秒级的。这就是为什么你能看到助手逐字「流」出来。

第二棒：Tauri 命令 → Harness

Rust 端的 send_message 命令收到请求后，调用 Harness::spawn_run。Harness 是「总调度员」——它管理所有 session 的生命周期：谁在跑、谁挂起了、谁该被唤醒。

CODE — apps/desktop/src/lib.rs 

async fn send_message(
    app: AppHandle,
    session_id: String,
    content: String,
    ...
    on_event: Channel<EngineEvent>,
) -> AppResult<()> {
    let core = core(&app)?;
    harness.spawn_run(...)
}

Harness 不自己跑模型。它只负责「调度」——把参数组装好，然后 spawn 一个异步任务，让 agent_loop 在后台跑。
