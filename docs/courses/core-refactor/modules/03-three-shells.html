三个壳，三种搬法

收口的目标一样——都改用 to_wire。但三个壳的现状不同，搬过来的"动作"也不同。像三间老房子翻新：有的拆旧墙就行，有的整间推平重盖，有的得小心保留承重结构。

1
桌面：拆掉旧翻译，接上 to_wire

删掉它那套 280 行的翻译函数和自定义事件类型，所有出口直接调 to_wire。前端完全无感。

2
网页：整个翻译文件删掉

它那套翻译独占一个文件，连同自定义事件类型一起整文件删除，改用 to_wire。

3
命令行：保留类型，只统一字段形态

它的事件类型有"承重作用"不能拆（下个模块详解），但能让字段值复用同一套规范。

如果三个壳能开个会

收口前，三个壳各自为政。我们把这次重构想象成一场群聊——看它们怎么达成"以后都听 to_wire 的"这个共识：

📡
to_wire（新广播室）

各位，从今天起，事件翻译都来找我。你们别再各写各的了。

桌面

📡
to_wire

不会。早在我上线那天，就埋了一个对照测试，逐字节证明我翻出来的和你旧的一模一样。前端收到的 JSON 完全相同。

🌐
网页

我之前偷懒，只翻译了一部分事件。换成你以后，我会收到更多种类的事件，前端能扛住吗？

📡
to_wire

能。那些"多出来的"事件，桌面一直在发，你俩共用同一套前端代码——它早就会处理了。你反而是白捡了功能，向桌面看齐。

⌨️

📡
to_wire

对，你是特例，留着你的类型。但你那些字段的"写法"可以复用我的规范——这样三家的字段值就一致了。细节下个模块讲。

📡

桌面：一行替换，删掉一整套

桌面的搬法干净利落。它的"观察者"原本在每个事件出口调旧翻译函数 agent_event_to_engine_event，现在统统换成 to_wire：

CODE · chat.rs（改动示意） 
// 改之前：调桌面自己那套翻译
if let Some(ev) = agent_event_to_engine_event(event) {
  (self.emit)(ev);
}

// 改之后：调全局唯一的 to_wire
if let Some(ev) = protocol::to_wire(event) {
  (self.emit)(ev);
}
大白话

原本：把事件交给桌面自己写的翻译机。

如果翻得出来，就发给前端。

现在：把事件交给全世界唯一的翻译机 to_wire。

逻辑一模一样——只是换了翻译机的牌子。

那套 280 行的旧翻译机，从此可以整个删掉。

🎁
顺手清掉的"僵尸代码"

搬迁过程中还发现两个文件谁都没在用——其中一个甚至依赖另一个早被删掉的文件，根本编译不过的僵尸。重构常常顺带照出这种积灰角落。

收口的净效果

🗑️

删掉

桌面 280 行翻译 + 自定义事件类型；网页整个翻译文件；2 个僵尸死文件

✅

留下

一个 to_wire，三个壳共用。改翻译规则，全世界只有一处可改

🎁

白捡

网页向桌面看齐，自动收到以前漏掉的 19 种事件，功能更全

🔑
"前端无感"是怎么做到的

因为新翻译 to_wire 吐出的 JSON，和桌面旧翻译逐字节一致——这件事在写新翻译那天就用一个测试钉死了。所以删旧的、换新的，前端那边完全不知道发生过什么。这是安全重构的精髓：先证明等价，再替换。
