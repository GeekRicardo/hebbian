# Desktop 浅色低对比正式样式设计

## 目标

这份文档定义 Hebbian Desktop 浅色低对比正式界面的视觉方向和交互逻辑。此前前端风格方案已通过用户确认，现在作为 Desktop 默认界面应用。

正式入口：

```text
pnpm tauri dev
```

Desktop 默认渲染新的三栏工作台。

## 设计原则

1. **保留 Hebbian 的产品结构**：左侧项目/对话列表、中间聊天区、右侧工作区、真实输入框、设置工作台都沿用 Hebbian 既有功能，不用外部产品的信息架构替换现有能力。
2. **只参考视觉气质**：采用浅色、低对比、冷灰、白色卡片、轻阴影、圆角、克制分割线；不做像素级复刻。
3. **正式应用，业务隔离**：样式集中在 Desktop shell 和配套 CSS 中；真实组件只暴露必要 class 或轻量布局钩子，不改变核心业务行为。
4. **真实组件优先**：输入框、模型选择器、右侧工作区、设置页尽量使用真实组件。开发环境或浏览器调试拿不到 Tauri 数据时，允许提供只用于展示的 fallback 数据。
5. **用户文案讲人话**：UI 字符串避免暴露内部路径、字段名、source 枚举、Rust 类型名等实现细节。

## 范围

### 包含

- 正式 Desktop shell 和三栏工作台。
- 左侧 sidebar 的浅色卡片式重构。
- 左侧 sidebar 底部设置旁的色系圆环控制。
- 中间聊天区的浅色、低对比样式。
- 真实 `ChatInput` 的正式换肤。
- 真实 `ModelPickerButton` 在输入框内的样式和空会话 fallback。
- 真实 `RightSidebar` 保留结构，并使用更宽的工作区展开尺寸。
- 设置页从小弹窗变为全窗口设置工作台，并重新分组。

### 不包含

- 不改 agent-core、协议、storage、权限、模型请求逻辑。
- 不做任何外部界面的像素级复制。

## 架构定位

本设计只影响 Desktop surface 的前端呈现层，符合架构.md 中“Surface 是壳”的原则。Desktop 仍只负责同步 API 数据展示、用户操作翻译和事件渲染，不实现 agent 业务逻辑。

正式 Desktop shell 组合：

```text
DesktopShell
├── DesktopSidebar       左侧项目/对话列表
├── DesktopChat          中间聊天区 + ChatInput
└── RightSidebar         右侧工作区，保留真实组件
```

## 整体布局

### 三栏结构

1. **左侧 sidebar**：固定宽度，内部是一张圆角 list 卡片，而不是铺满全高的平面侧栏。
2. **中间聊天区**：占据主空间，顶部轻 header，中间消息流，底部真实输入框。
3. **右侧工作区**：保留原 `RightSidebar` 的信息层级、工具卡片、状态区和交互，仅套浅色低对比样式。

### 视觉层级

- 页面背景：冷灰白。
- 主要容器：白色或近白卡片。
- 边框：低对比细线，只用于区分容器边界。
- hover：用浅灰底色和轻微阴影表达，不用重边框。
- active：用更稳定的浅色填充、较深文字、必要时加细色条，不使用高饱和大面积强调。

### 色系控制

左侧 sidebar 底部设置按钮旁增加一个小型调色入口，用于快速试不同主色系。

交互：

- 调色图标放在左侧 sidebar 底部设置按钮右侧，和设置在同一行并靠右。
- 点击图标展开一个小浮层。
- 浮层优先展示 4 个精调预设：冰湖蓝绿、雾蓝灰、青瓷灰、月白灰。
- 点击预设直接切换整套色系。
- 预设下方保留圆形色相环和线性滑杆，用于在好看预设基础上微调。
- 拖动色相环时，根据圆心角度计算 hue；滑杆用于精调同一个 hue。
- 颜色变化只影响当前 Desktop shell 的视觉 token，不写入用户设置。

色彩策略：

- 默认推荐使用 4 个预设而不是自由拖动：冰湖蓝绿用于默认清爽感，雾蓝灰用于低对比冷静感，青瓷灰用于轻微青绿色调，月白灰用于最克制的近中性色。
- 不让用户逐项改颜色，而是用一个 hue 驱动整套 token。
- 主色、辅色、柔和背景、sidebar 背景、中间 chat 背景氛围、右侧 sidebar 背景、用户消息轻染色、输入框 hover、边框、阴影都由这个 hue 做线性变换。
- 中间 chat 区的多色插画卡片保留原始多色结构；调色时按主色 RGB 相对基准色的差值，对卡片内每个基础色施加相同 RGB 偏移量，保持“多种颜色之间的关系”不丢。
- 右侧 sidebar 跟随同一 hue 调整背景、卡片和 hover，但只使用低透明度浅色，避免抢走中间 chat 焦点。
- 明度和透明度保持在浅色低对比范围内，避免拖到高饱和主色后破坏整体克制感。
- 语义色如 danger / amber / green 不跟随 hue，避免错误、警告、成功状态失去辨识度。

## 左侧 sidebar

### 顶部标签

左侧卡片顶部保留两个轻量 tab：

- `code`
- `chat`

当前正式界面中 `code` 为 active。tab 用于延续 Hebbian 原有入口感，不引入“连接手机”“插件”“定时任务”等不属于当前需求的入口。

### 新建对话

“新建对话”是浅色实按钮，位于 tab 下方。

行为：

- 点击主按钮：创建不绑定项目的新对话。
- 点击项目行 hover 出现的 `+`：创建绑定该项目的新对话。
- 点击默认项目的 `+`：创建不绑定项目的新对话。

### 项目分组

项目列表由 workspace project 和 session 共同生成：

- 每个已配置项目形成一个项目分组。
- session 优先按 `project_id` 归组。
- 没有 `project_id` 时，可按 session 的工作目录和项目主目录匹配。
- 未匹配到项目的 session 进入“默认项目”。
- “默认项目”始终显示，即使当前没有对话，避免用户以为未归类对话入口消失。

项目标题行展示：

- 折叠/展开图标。
- 文件夹图标。
- 项目名。
- 项目短路径或“未归入项目的对话”。
- 对话数量。

项目标题行交互：

- 点击标题主体：展开或折叠该项目的对话列表。
- hover 项目标题：在同一个 hover 框内部右侧显示 `+` 新建按钮。
- `+` 不应漂浮到 hover 框外，也不应挤压项目名导致“默认项目”显示不全。

### 对话行

每个项目下展示最近对话。

对话行展示：

- 对话标题。
- 模型名或摘要信息。
- 更新时间。
- 运行中 / 未读完成等状态提示。

对话行交互：

- 点击行：打开该对话。
- 当前对话：使用浅色 active 背景和更清晰文字区分。
- hover 行：显示删除按钮。
- 删除按钮必须在行 hover 范围内，视觉上属于当前对话行。
- 点击删除：弹出确认，再调用真实删除逻辑。

### 列表溢出

项目过多或对话过多时，左侧卡片内部滚动，不撑爆窗口。

当前每个项目先显示最近 10 条对话。后续如果对话数量继续增长，应补充“查看更多”或项目内虚拟列表。

## 搜索交互

搜索位于“项目”标题行右侧，默认是紧凑状态。

状态：

- 默认：只显示轻量搜索入口。
- focus 后：展开输入框和搜索选项。
- 输入为空：展示所有项目分组和对话。
- 输入非空：只保留匹配的对话；项目分组仍按项目结构展示。

匹配范围：

- 对话标题。
- 模型名。

搜索选项：

- `Aa`：区分大小写。
- `.*`：正则表达式。

正则行为：

- 正则有效：按正则匹配。
- 正则无效：当前搜索结果为空，不弹阻塞式错误。
- 后续生产化可以增加轻量错误提示，例如输入框边缘提示“表达式无效”。

## 中间聊天区

### Header

顶部 header 只承载当前上下文的轻信息，例如当前对话、项目、状态。视觉上保持低对比，不抢输入框和消息流焦点。

### 消息流

消息流保留 Hebbian 原有消息表达：

- 用户消息。
- Assistant 消息。
- tool call / tool result 的摘要。
- markdown 渲染。

视觉策略：

- 用户消息使用轻色气泡或右侧对齐。
- Assistant 消息以正文块为主，减少重边框。
- tool 信息使用更轻的辅助色，作为消息流中的二级信息。
- 空状态中间卡片复刻参考界面的插画式卡片结构：窗口点、右上小按钮、左侧占位栏、浅网格、中央 Hebbian logo 卡片、底部信息线和装饰气泡都要存在，不能只放一个孤立 logo。
- 卡片下方显示标题“你想用 Hebbian 做什么”。

### 输入框

正式界面必须使用真实 `ChatInput`，不能使用假画控件。

保留元素：

- `+` 附件入口。
- 命令入口。
- 模型选择器。
- RunMode。
- Effort / thinking 设置。
- cache / context 状态。
- 发送按钮。
- 运行中取消按钮。

交互策略：

- 二级设置行默认展开，不再提供底部折叠小按钮。
- 二级设置行不再有独立底层卡片；只直接显示 RunMode、Effort、cache/context 等元素，字号比输入框内主工具条更小。
- 运行中不自动折叠设置行。
- 运行中空间不足时，RunMode / Effort 允许收缩为图标，但不能消失，也不能破坏取消/发送主操作。
- 输入框整体使用浅色背景、低对比边框、轻 hover，而不是深色强阴影。

## 模型选择器

模型选择器必须是输入框里的真实 `ModelPickerButton`，不是输入框上方的 mock 卡片。

### Trigger

默认状态：

- 类似轻文本或轻胶囊。
- 不显示明显外边框。
- 不像独立按钮那样抢视觉焦点。

hover / open 状态：

- 出现浅色圆角背景。
- 背景两端必须接近半圆，整体像轻胶囊，不像矩形按钮。
- 仍不显示边框或描边，只用背景变化表达可交互状态。
- 展示当前模型名、thinking 图标、思考强度图标和下拉箭头。

### 数据来源

真实 Tauri 对话中：

- 使用真实 providers。
- 使用当前 session 的 provider / model / reasoning 配置。
- 切换模型时调用真实 `switchProviderModel`。
- 修改 thinking / effort 时调用真实 `setReasoning`。

开发调试或无 current session 时：

- 如果 store 中已有 enabled providers，则展示这些 providers。
- 如果没有真实配置，则使用少量 mock providers/models，只用于下拉样式兜底。
- mock 数据不得进入持久化，也不影响真实 provider 配置。

### Popup 结构

目标交互是“先选 provider，再选 model”。当 provider 和 model 很多时，popup 不能无限撑高或撑宽。

推荐结构：

```text
模型选择 popup
├── 第一层框：标题“供应商” + Provider 列表（可滚动）
│   └── 参数区：选择 model 后出现 thinking / effort / 长上下文设置
└── 第二层框：标题“某供应商的模型” + 选中 provider 的 Model 列表（可滚动）
```

行为：

- 打开 popup 时，第一层框默认选中当前 provider。
- 第一层 provider 框左侧永远对齐输入框里的 model id 左侧，不因点击 provider、出现 model 框或参数区而横向跳动。
- 点击第一层框中的 provider，右侧新生成一个独立 model 框，而不是把 model 列表塞进 provider 列表内部。
- provider 很多时，第一层框内部滚动。
- model 很多时，右侧 model 框内部滚动。
- 当前 provider 使用浅色直角底色标识；当前 model 使用浅色 active 状态标识。
- 第一层 provider 列表只纵向滚动，不出现横向滚动条。
- 点击 model 后立即切换模型，但不马上关闭 popup；第一层框底部出现该模型的参数区。
- 参数区用于调整 thinking 开关、思考强度、长上下文开关。
- 参数调整使用真实 `setReasoning`，不伪造状态。
- 用户点“完成”后关闭整个模型选择器。
- popup 最大高度受视口限制，例如不超过 60vh。

### Reasoning controls

Reasoning controls 固定在 popup 底部，不随 provider/model 列表滚走。

包含：

- thinking 开关。
- 思考强度选项。
- 支持长上下文的模型显示长上下文开关。

展示规则：

- 模型支持 thinking 时显示 thinking 开关。
- 模型支持 effort 时显示强度分段选项。
- 模型支持长上下文时显示长上下文开关。
- 不支持的能力不展示，不使用禁用控件堆满界面。

## 输入框状态区

输入框下方右侧使用一个合并状态胶囊，不再把 cache 和上下文拆成两个独立图标。

展示规则：

- 图标主体沿用原上下文进度圆环。
- 圆环表示当前上下文百分比。
- 圆环旁展示 cache 命中率和上下文百分比。
- hover 面板同时展示 token 输入/输出、缓存命中、缓存写入、上下文用量。
- 点击该状态胶囊仍触发上下文压缩；压缩中不重复触发。

## 右侧工作区

右侧 `RightSidebar` 保留原结构和功能，但正式界面中按参考图做成更明显的右侧大面板，而不是窄工具抽屉。

布局策略：

- 折叠态仍是窄图标列，保留原展开/切 tab 逻辑。
- 点击展开后，默认宽度约 560px，明显挤压中间聊天区，形成左导航 / 中间聊天 / 右工作区的三栏 coding workspace。
- 用户仍可拖动左边缘调宽；范围约 420px 到 860px。
- 右侧栏使用独立于旧默认侧栏的宽度记忆，避免继承旧 320px 宽度。

样式策略：

- 背景、卡片、边框、hover 状态调整为与 Desktop shell 一致的浅色低对比风格。
- 右侧面板视觉上接近“文件 / 变更 / 本地状态”工作区：大面积近白背景、低对比搜索框和空状态，不使用重边框。
- 不改变工具卡片、审批、事件流、编辑快照、上下文状态等业务结构。
- 不移动功能入口，不新增无关功能。

## 设置页

设置页从小弹窗改为全窗口设置工作台。

### 布局

```text
设置工作台
├── 左侧：分组导航
└── 右侧：当前设置面板
```

左侧分组：

- 基础
- Agent
- 扩展
- 调试

Tab 归类：

- 基础：通用、对话、模型、供应商。
- Agent：Agents、记忆、权限。
- 扩展：Skills、插件、Hooks、MCP。
- 调试：日志。

### 交互

- 打开设置：显示全窗口 overlay。
- 切换 tab：右侧内容切换，左侧 active 状态更新。
- 关闭设置：返回当前界面。
- 保存/修改逻辑沿用真实设置页，不重写业务。

### 调试 fallback

开发环境拿不到 Tauri app settings 时，使用 fallback settings 避免空白。

fallback 只解决“界面能看见布局”的问题，不代表真实默认配置，也不写入持久化。

## Mock 与真实组件边界

真实组件：

- `ChatInput`。
- `ModelPickerButton`。
- `RightSidebar`。
- `AppSettingsDialog` 的主要设置结构。
- session / project / provider store 操作。

允许 mock / fallback 的内容：

- 无 current session 时的模型 provider/model 展示数据。
- 开发调试无法读取 Tauri 设置时的设置页 fallback。
- 空状态文案。

禁止：

- 用假输入框替代真实 `ChatInput`。
- 用输入框上方的假模型卡片替代真实模型选择器。
- 用外部产品功能替换 Hebbian 原功能。
- 在 UI 文案里暴露内部路径、source 枚举、字段名。

## 状态与错误处理

### 创建对话失败

- 调用真实 `newSession`。
- 失败时 toast 展示错误。

### 删除对话失败

- 删除前确认。
- 调用真实 `deleteSession`。
- 失败时 toast 展示错误。

### 模型切换失败

- 调用真实 `switchProviderModel`。
- 失败时 toast 展示错误。
- 不在前端伪造成功状态。

### 正则搜索失败

- 无效正则不阻塞 UI。
- 当前策略是匹配为空。
- 后续可以增加非阻塞提示。

## 响应式与溢出策略

- 左侧 sidebar 保持卡片宽度稳定，内容内部滚动。
- 中间聊天区优先保留输入框和消息流可用性。
- 右侧工作区保留原宽度策略，小屏时按现有产品能力处理。
- 模型 popup 设置最大高度和内部滚动，provider/model 多时不撑爆窗口。
- 设置页全窗口 overlay 在小屏下仍保持左侧导航和右侧内容可滚动。

## 验收标准

1. Desktop 默认展示浅色低对比三栏工作台，不再需要 URL 预览开关。
2. 左侧 sidebar 是圆角 list 卡片，不是平铺侧栏。
3. “默认项目”始终可见，标题不被 `+` 挤压或遮挡。
4. 项目 hover 的 `+` 位于项目 hover 框内。
5. 对话 hover 的删除按钮位于对话行 hover 框内。
6. 输入框使用真实 `ChatInput`，保留原元素和交互。
7. 模型选择器使用真实 `ModelPickerButton`，默认 trigger 无明显外边框。
8. provider/model 很多时，下拉菜单内部滚动，不撑爆视口。
9. reasoning controls 固定在模型 popup 底部。
10. 右侧工作区保留原功能结构，展开后是更宽的大面板。
11. 设置页为全窗口工作台，并按“基础 / Agent / 扩展 / 调试”分组。
12. 类型检查通过：`pnpm exec tsc --noEmit`。

## 后续决策点

1. 项目内超过 10 条对话时，是继续截断、增加“查看更多”，还是引入虚拟列表。
2. 正则错误是否需要即时提示。
3. 右侧工作区是否需要进一步减少信息密度。
4. 设置页各 tab 内部是否继续做更细的卡片化重排。
